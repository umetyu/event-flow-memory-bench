# Zhu 2019 [56]のUZH再学習

識別名は`zhu2019-uzh`、実行プロトコルは`zhu2019-reimplementation-v1`です。著者配布コード・重みの再実行ではなく、論文に基づく再実装です。[論文報告値](../configs/literature/zhu2019_table1.csv)は別条件として保持します。実装が動くことと論文精度を再現することは別です。

参照: [CVPR 2019論文](https://openaccess.thecvf.com/content_CVPR_2019/html/Zhu_Unsupervised_Event-Based_Learning_of_Optical_Flow_Depth_and_Egomotion_CVPR_2019_paper.html)、[著者掲載PDF](https://www.cis.upenn.edu/~kostas/mypub.dir/alex19cvpr.pdf)、[コード公開に関する著者の回答](https://github.com/daniilidis-group/EV-FlowNet/issues/12#issuecomment-644892449)。

## 数式とネットワーク

- signed 9-bin voxel、時間方向の線形補間。配布HDF5の座標は整数で、独自の再rectificationは行いません。
- Fig. 2の4 encoder・2 residual block・4 decoder。各decoderの予測を次のdecoderへ連結し、全4段へ損失を適用します。
- native出力は各段の空間解像度でのpixel/bin。lossでは座標をその段の解像度へ変換し、時間を0〜8へ変換します。
- 平均timestamp画像を極性別にbilinear splatし、開始・終了時刻へのwarpの両方で二乗和を計算。両方向とも元のtimestampを使い、active-pixel数で割りません。
- u,vそれぞれの4近傍Charbonnier和、係数1。4近傍の有向和なので各無向辺を2回数えます。

上記の新しいlossはHagenaarsのlossとは独立です。encoder-decoder部品はMITで収録済みの`MultiResUNet`を再利用します。

## 明記する実装上の選択

正式なCVPR 2019実装との照合ができていないため、次は本基盤の具体的な選択です。これらを原論文の確認済み設定とは主張しません。

| 項目 | この再実装 |
|---|---|
| encoder channels | 64, 128, 256, 512 |
| decoder channels | 256, 128, 64, 32 |
| convolution | 3×3、ReLU、normalizationなし |
| decoder upsampling | bilinear、align_corners=False |
| flow head | 1×1 linear、初期weight標準偏差0.001、bias 0 |
| 空間scaleのloss | 各段のnative解像度で評価し、4段を等重みで加算 |
| timestamp分母epsilon | 1e-6 |
| Charbonnier epsilon | 1e-3 |
| optimizer | Adam、lr=2e-4、勾配norm clip=100 |
| 学習量 | seed 0、100 epochs、batch 8 |
| 入力正規化 | 追加正規化なし |

## UZHでの変更点

学習は既存の著者配布UZHのrecording-level split（学習116本、検証24本）を使います。原法のMVSEC outdoor_day2と256×256中央cropに対し、本実験はUZHの128×128クロップです。1入力30,000イベントで、非重複の入力窓ごとに更新します。500,000イベントの各ファイルから16窓を使い、末尾20,000イベントは除外します。1 epochの学習イベント数は55,680,000です。空間・極性flipを使用します。

検証はUZHだけで行い、各30k窓について既存上流実装のRSAT（flow scale=8）を計算し、全窓の平均が最小のcheckpointを選択します。forward warp後の画面内イベント割合も記録します。MVSECはcheckpoint選択・hyperparameter調整に使いません。

lossと入力窓が異なるので、この結果を既存の`matched-v1`と同一の学習条件とは扱いません。[56]報告値との違いも学習データだけの効果とは断定できません。

## 実行

```bash
# 既存のCUDA Python環境と専用作業ディレクトリを指定
export EFBENCH_PYTHON=/path/to/cuda-python
export EFBENCH_ROOT=/path/to/event-flow-memory-bench
export PYTHONPATH="$EFBENCH_ROOT/src:$EFBENCH_ROOT/external/runtime-deps"

# 全テスト + 実データ20更新 + UZH検証1本。学習checkpointは保存しない。
EFBENCH_SMOKE_UPDATES=20 sbatch --time=00:30:00 scripts/slurm_izar_zhu2019.sh

# seed 0の100 epoch。その後best.ptでMVSEC dt1/dt4を自動評価。
sbatch scripts/slurm_izar_zhu2019.sh
```

`EFBENCH_SMOKE_UPDATES`はsmoke投入時だけ指定します。full runへ引き継がないでください。設定は[uzh_zhu2019.yml](../configs/uzh_zhu2019.yml)。run directoryは既存なら上書きせず停止します。epoch境界から再開する場合は`EFBENCH_RUN`と`EFBENCH_RESUME=/.../latest.pt`を指定します。再開時はsplit・設定の一致を検証します。

`run.json`にはソースhash、設定、split、PyTorch/GPU、Git revisionを保存します。`epochs.jsonl`はloss、RSAT、イベント数と時間、`latest.pt`と`best.pt`は再開・評価用です。`completed.json`は学習完了時のみ作成します。

## MVSEC評価の定義

GT区間の終端より前のイベントだけを使い、outdoorでは直近30k、indoorでは15kを入力します。入力が全数揃わない冒頭とイベントのない区間はスキップして件数を記録します。pixel/bin出力を`8 × GT区間秒数 / 入力秒数`で変位へ換算します。

採点はGTが有効でGT区間内にイベントがある画素。AEE、3 px AND GTの5%を超える外れ値率、原法に対応する3 pxのみの外れ値率を別キーで保存します。GT区間ごとの値の単純平均です。元のHagenaars評価は入力partitionとmaskが異なるので、同一採点条件の再現とは扱いません。

## 検証内容

9-bin補間、極性分離と境界splat、双方向で同じtimestampを使うこと、active-pixel正規化を入れないこと、有限差分との勾配一致、u/vのsmoothnessの独立性、空間・時間の単位換算、全段のbackward、checkpoint再開の一致、smokeと本学習の区別、MVSEC dt1/dt4の因果性をテストします。テスト通過を論文精度の再現とは主張しません。
